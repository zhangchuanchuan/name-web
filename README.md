# 取名工坊 · 汉字取名器

一个纯静态的起名网站：**先按条件把可用的汉字挑出来，再自动排列组合成名字，最后导出**。
没有后端、没有构建步骤、没有第三方运行时依赖——`data/` 里是离线生成好的字库 JSON，前端是原生 ES Module。

覆盖需求：

| 需求 | 实现 |
|---|---|
| ① 常见字字库 | 《通用规范汉字表》一级 3500 + 二级 3000 + 三级 1605，实际入库 **7485 字**（含拼音、声调、笔画、康熙笔画、部首、结构、五行、造字法、释义、真实人名热度、性别倾向） |
| ② 选择姓氏 | 内置 **1074 个姓氏**（含 56 个复姓）与人口序，可搜索、可按人口排序，也可手动输入任意姓氏 |
| ③ 字数条件 | 单字名 / 双字名（复姓 + 双字 = 四字名） |
| ④ 逐字限定 | 每个字位**独立设置**：笔画范围（可切换康熙笔画）、声调多选、汉字结构、部首、五行、声母、韵母、字库级别、释义关键词、性别倾向、避开爆款字、排除字、白名单 |
| ⑤ 挑字 + 排列组合 + 导出 | 实时显示「满足条件的字」池；按整名规则排列组合；支持 **CSV / TXT / JSON** 导出（结果、候选字池、整个字库都能导） |

## 快速开始

```bash
cd name-web
node server.mjs          # 或 npm start
# 打开 http://127.0.0.1:8777/
```

> 必须通过 HTTP 访问（`data/*.json` 是 fetch 加载的），直接双击 `index.html` 不行。
> 任何静态服务器都可以，例如 `python3 -m http.server 8777`；`server.mjs` 只是零依赖的替代品，顺带做了 gzip。

### 分享链接

- `?surname=李` 指定姓氏
- `&preset=classic` 直接套用某个预设：`girl` / `boy` / `classic` / `rare` / `single` / `wuge`
- `&len=1` 指定单字名
- `&view=browse` 直接打开字库浏览

例：`http://127.0.0.1:8777/?surname=李&preset=classic`

## 功能细节

### 逐字条件（第 1 字 / 第 2 字分别设置）

- **笔画范围**：1–40 画，可勾选按**康熙笔画**计算（界面会实时显示每个 chip 在当前条件下的可用字数）
- **声调**：阴平 / 阳平 / 上声 / 去声 / 轻声多选。多音字默认「任一读音命中」（如「乐」既能按 lè 也能按 yuè 匹配），可在高级里关掉
- **汉字结构**：左右 / 上下 / 独体 / 半包围 / 全包围 / 左中右 / 上中下 / 品字 / 未收录
- **部首**：200+ 个部首可选，带搜索框
- **五行**：金木水火土（来自 cnchar-info）
- **声母 / 韵母**：23 个声母（含零声母）、全部韵母，带搜索
- **字库级别**：一级 / 二级 / 三级
- **释义关键词**：如「美玉 光明 温和」，空格分隔命中任一即可；带否定语境保护（「神志不清」不会命中「清」）
- **性别倾向**：按 105 万人名语料统计，可选「偏女性用字 / 偏男性用字」并设阈值
- **用字范围**：只用人名语料中出现 ≥N 次的字（默认 1，即先挡掉几乎无人使用的生僻字）
- **避开爆款字**：排除人名语料热度前 N 名的字
- **排除字 / 白名单**：也可以直接在候选字列表里**点字排除**

### 整名规则

- 名内不重复用字
- 名字两字偏旁不重复 / 连姓氏一起算
- 名字两字结构不同、五行不同
- 五行相生（名内、或与姓氏相生）
- 声调搭配：相邻不同调 / 全名各字声调互不相同 / 指定声调模式（如 `142` 含姓、`42` 仅名字）
- 排除不吉字与负面谐音（「吴用」→ 无用、「张卫生」→ 卫生）
- 再排除连读成常用词（更严格）
- **五格剖象**（康熙笔画 + 1–81 数理）：五格无凶数 / 人格地格总格皆吉 / 至少 N 格为吉 —— 民俗参考，默认关闭

### 排序

- **推荐**（默认）：把「用得太少（<20 次）」和「用得太烂（>3000 次）」都降权，只留下真实有人用、又不撞车的字
- 冷门优先 / 热门优先 / 总笔画升降序 / 拼音序 / 五格得分

> 结果默认上限 20000 条。**生成前会先按排序键给候选字排队**，所以被截断下来的两万条也是排序意义上最优的那一批，不会偏向字表顺序。

## 重建字库

```bash
cd tools
npm install
node build-data.mjs     # 首次会联网下载约 44 MB 源数据到 tools/.cache
node smoke-test.mjs     # 49 项自测
```

数据来源：

| 数据 | 来源 |
|---|---|
| 字表 | [rime-aca/character_set](https://github.com/rime-aca/character_set) 的《通用规范汉字表》 |
| 读音 / 笔画 / 部首 / 释义 | [pwxcoo/chinese-xinhua](https://github.com/pwxcoo/chinese-xinhua)（新华字典数据集） |
| 结构 / 五行 / 造字法 / 多音字 | [theajack/cnchar](https://github.com/theajack/cnchar)（cnchar-info、cnchar-radical 插件） |
| 姓名用字热度 / 性别倾向 | [wainshine/Chinese-Names-Corpus](https://github.com/wainshine/Chinese-Names-Corpus) 120 万人名语料（统计时剔除姓氏用字，实际统计 1,050,039 个人名） |
| 姓氏与人口序 | 同上语料库的姓氏表 |

### 数据口径与已知取舍

- 收录的是通用规范汉字表里**有规范读音、且在 BMP 基本区**的 7485 字；跳过 273 个扩展 B 区生僻字（无读音数据）与 1 个无笔画数据的字。
- 约 10% 的三级生僻字在 cnchar 与新华字典里都没有结构数据，统一标为「未收录」；一级字已做到 100% 覆盖（21 个人工补齐，如「剑」）。
- 约 150 个生僻字的拼音来自新华字典兜底（cnchar 未收录），字库浏览里以虚线标注、鼠标悬停有说明；这些字用字热度为 0，默认被「用字范围」挡在候选之外。
- 康熙笔画用「简体规范笔画 + 部首还原差额」近似（氵→水 +1、艹→艸 +3、阝 +5 等），与专门的字帖可能差 1 画，五格结果仅供参考。
- 不吉字与谐音词典是**保守黑白名单**，宁可漏判也不误伤「思、清、安」这类常用美字；释义关键词搜索基于词典释义文本，不是语义搜索。

## 部署到 GitHub Pages

本站是纯静态站点（无后端、无构建步骤），而且**全部用相对路径**，所以既能放在
`https://<用户名>.github.io/`，也能放在子路径 `https://<用户名>.github.io/<仓库名>/`。
仓库里已经准备好 `.gitignore`、`.nojekyll` 和 Actions 工作流，按下面任选一种即可。

### 第 0 步：推到 GitHub

先在 GitHub 上新建一个**空仓库**（不要勾选 Add README / .gitignore，避免首次推送冲突），然后：

```bash
cd name-web
git remote add origin https://github.com/<用户名>/<仓库名>.git   # 或 git@github.com:<用户名>/<仓库名>.git
git push -u origin main
```

> 仓库里已经有一次提交。`.gitignore` 已排除 `tools/node_modules/` 与 `tools/.cache/`（约 42 MB 的
> 第三方原始数据，可用 `npm run build:data` 重新下载），因此实际推送的只有约 1.6 MB。

### 方式 A：从分支发布（最简单，零配置）

1. 仓库 **Settings → Pages**
2. **Build and deployment → Source** 选 `Deploy from a branch`
3. **Branch** 选 `main`，目录选 `/ (root)`，Save
4. 等 1 分钟左右，访问 **`https://<用户名>.github.io/<仓库名>/`**

仓库根的 `.nojekyll` 会让 GitHub 跳过 Jekyll 处理，直接原样发布这些静态文件。

### 方式 B：用 GitHub Actions 发布（推荐，可控）

仓库已内置 `.github/workflows/deploy-pages.yml`，它只做三件事：挑出站点文件 → 上传 → 部署，
并且**只发布** `index.html`、`assets/`、`data/`、`.nojekyll`，`tools/` 与 README 不会进入站点。

1. 仓库 **Settings → Pages → Build and deployment → Source** 选 `GitHub Actions`
2. push 到 `main`（或在 **Actions** 页手动 `Run workflow`）
3. 部署完成后，Actions 里会直接给出站点 URL

### 两种方式怎么选

| | 方式 A 分支发布 | 方式 B Actions |
|---|---|---|
| 配置 | 点两下即可 | 需把 Source 改成 GitHub Actions |
| 发布内容 | 整个仓库（含 tools/、README） | 只有站点文件 |
| 构建频率限制 | 受「每小时 10 次构建」软限制 | 自定义工作流**不受**该限制 |
| 适合 | 就是现在这个纯静态站点 | 以后要加构建步骤、或只想发布部分文件 |

### Pages 的额度与限制（[官方文档](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)）

- 源仓库建议 ≤ 1 GB，**发布后的站点 ≤ 1 GB**（本站连数据一共约 1.6 MB）；
- 单次部署超过 **10 分钟**会超时（本站无需构建，秒级完成）；
- 软带宽上限 **100 GB/月**，软构建上限 **10 次/小时**（用自定义 Actions 工作流发布时不受构建次数限制）；
- 免费账号的 Pages 只支持**公开仓库**；私有仓库里的 Pages 需要 GitHub Pro / Team / Enterprise；
- GitHub Pages 不允许用于以商业交易为主的站点（做个人作品/工具没问题）。

### 后续更新

改了代码或字库后：

```bash
git add -A && git commit -m "update" && git push
```

用 Actions 方式会自动重新部署；用分支方式 GitHub 也会自动重新发布。
如果重新生成了字库（`npm run build:data`），`data/` 下的三个 JSON 会变化，一起提交即可。

### 自定义域名（可选）

仓库 **Settings → Pages → Custom domain** 填入域名，GitHub 会在分支里写入 `CNAME` 文件（用 Actions 方式时需要在
`_site` 里一并生成 `CNAME`，或改用分支发布）。DNS 侧按官方提示配置 A / CNAME 记录即可。
